PART 12: KEY TAKEAWAYS FROM ACADEMIC SOURCES
================================================================================

CONSENSUS & FAILOVER (MIT 6.824 2001-2025):
- Consensus is THE fundamental problem in distributed systems
- Paxos (1982-2001): Theoretically sound, hard to understand
- Raft (2013+): Easier to understand, equally sound
- Both solve: leader election, log replication, safety guarantees
- Failover: Automatic leader re-election when leader crashes
- All modern systems use one of these two protocols

STATE MACHINES & REPLICATION (Berkeley CS 162 / Caltech CS 143):
- Replicated State Machine (RSM): Core abstraction for fault tolerance
- Each replica maintains identical state
- Consensus protocol ensures all replicas process requests in same order
- Snapshots and checkpoints reduce recovery time
- Two-phase commit for multi-step transactions

PROGRAM ANALYSIS (Stanford CS 243-352):
- Abstract Syntax Trees (ASTs) are fundamental data structures
- Static analysis extracts program properties without running code
- Data flow analysis tracks how data moves through program
- Code transformation manipulates ASTs to refactor code
- Modern tools (tree-sitter, Comby) automate this for all languages

ASYNC SYSTEMS (Berkeley CS 162 + MIT async materials):
- Async I/O allows single thread to handle multiple connections
- State machines control program flow in async systems
- Tokio runtime manages task scheduling
- Memory safety crucial in concurrent systems
- Rust's type system prevents data races at compile time

PRACTICAL ENGINEERING (MIT 6.824 2020+ labs, real systems):
- Build incrementally: start with simple models, add complexity
- Test thoroughly: distributed systems are hard to debug
- Use proven algorithms: don't invent new consensus protocols
- Monitor and measure: observability is critical
- Plan for failures: they WILL happen
